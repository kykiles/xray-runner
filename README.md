# xray-runner

Простая программа для запуска VPN на базе [Xray-core](https://github.com/XTLS/Xray-core).
Вы вставляете ссылку или подписку от вашего VPN-провайдера, выбираете сервер из списка —
и программа поднимает соединение. Есть два режима: системный прокси или полноценный
VPN (TUN). При выходе программа сама всё за собой убирает.

Работает на **Linux** и **Windows**.

---

## Что нужно для запуска

Рядом с программой должны лежать несколько файлов (обычно они уже в комплекте):

| Файл | Что это |
|---|---|
| `xray-runner` (или `xray-runner.exe`) | сама программа |
| `xray` (или `xray.exe`) | ядро Xray-core — движок соединения |
| `template.json` | шаблон настроек (менять не нужно) |
| `geoip.dat`, `geosite.dat` | базы для маршрутизации по странам/сайтам |
| `.env` | файл настроек (можно не трогать) |

На Windows для режима VPN дополнительно нужен `wintun.dll`.

## Как пользоваться

### 1. Добавьте свою подписку или ссылку

Проще всего — запустить программу и добавить подписку прямо в меню (кнопка **добавить**
в списке подписок). Ссылки и подписки хранятся в файле `subscriptions.txt` рядом с
программой, по одной на строку.

Поддерживаются ссылки `vless://`, `ss://` (Shadowsocks), `trojan://`, `vmess://`,
а также URL-подписки, которые провайдер даёт одной строкой.

### 2. Запустите программу

- **Linux:** откройте терминал в папке с программой и выполните `./xray-runner`.
  Для режима VPN (TUN) нужны права root: `sudo ./xray-runner`.
- **Windows:** запустите `xray-runner.exe`. Для режима VPN — от имени администратора.

### 3. Выберите сервер

Откроется список. Управление с клавиатуры:

| Клавиша | Действие |
|---|---|
| `↑` / `↓` (или `k` / `j`) | двигать курсор |
| `Enter` | подключиться к выбранному серверу |
| `/` | поиск по названию или адресу |
| `b` | замерить пинг серверов и отсортировать по скорости |
| `r` | обновить список из подписки |
| `Esc` / `←` | назад |
| `q` или `Ctrl+C` | выход |

### 4. Работа во время подключения

После подключения появится экран статуса. На нём видно сервер, режим, время работы и
состояние связи. Клавиши:

| Клавиша | Действие |
|---|---|
| `m` | переключить режим PROXY ⇄ TUN на лету |
| `r` | перезапустить соединение |
| `Esc` | отключиться и вернуться к списку серверов |
| `q` | выйти из программы |

Программа сама следит за связью и, если соединение несколько раз подряд обрывается,
автоматически перезапускает ядро.

> **Про строку «связь».** Сразу после подключения ядру нужна пара секунд, чтобы
> прогреться. Программа делает несколько попыток проверки, прежде чем показать
> «нет связи», поэтому ложных срабатываний в первый момент быть не должно. Если
> всё же увидели «нет связи» — нажмите `r`, чтобы перепроверить.

## Режимы: PROXY и TUN

**PROXY (по умолчанию)** — программа поднимает локальный прокси и прописывает его в
настройки системы. Через VPN пойдёт трафик приложений, которые уважают системный прокси
(браузеры и большинство программ). Прав администратора не требует.

- SOCKS5: `127.0.0.1:10808`, HTTP: `127.0.0.1:10809`

**TUN (полный VPN)** — весь трафик системы идёт через VPN, как у обычного VPN-клиента.
Требует прав root (Linux) или администратора (Windows). Можно включить «kill switch»,
чтобы при обрыве не было утечки реального IP (`KILL_SWITCH=true` в `.env`).

Переключиться между режимами можно прямо на экране статуса клавишей `m`. Выбранный режим
запоминается до следующего запуска.

## Обновление ядра и баз

В списке подписок нажмите кнопку **обновление**. Откроется экран, где можно:

- **Обновить ядро xray** — программа скачает свежие версии с официального репозитория и
  предложит список. В шапке экрана показано, **какое ядро установлено сейчас** («Текущее
  ядро: …»), а напротив совпадающей версии в списке стоит пометка **(установлено)** —
  так видно, обновление это или откат.
- **Обновить гео-базы** — свежие `geoip.dat` / `geosite.dat`.

## Частые проблемы

**«Порт занят другим процессом».** Обычно это значит, что уже запущен либо второй
экземпляр этой программы, либо другой VPN/прокси, занявший тот же локальный порт.
Закройте сторонний VPN или второй экземпляр и попробуйте снова.

**Про lock-файл.** Программа создаёт рядом файл `xray_config.json.lock`, чтобы не
запуститься дважды. Если прошлый запуск завершился аварийно (например, было закрыто окно
или процесс был убит), файл может остаться. **Удалять его вручную не нужно** — при
следующем запуске программа проверит, жив ли владелец, и если нет — сама заберёт lock.
Отказ появится только тогда, когда действительно работает второй экземпляр.

**В режиме TUN нет связи.** Проверьте, что запустили с правами root/администратора.
Если маршруты не поднялись — смотрите раздел ниже про TUN.

## Для продвинутых пользователей

### Сборка из исходников

```bash
# под текущую ОС
task build

# под Linux (в папку xray_linux/) и Windows (в папку xray_windows/)
task build:linux
task build:windows
```

Задачи `build:linux` / `build:windows` кладут рядом с бинарником свежую копию этого
README.

### Настройки `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VLESS_URL` | — | VLESS или `ss://` ссылка (fallback, если нет `subscriptions.txt`) |
| `SUBSCRIPTION_URL` | — | URL подписки (приоритет выше, чем `VLESS_URL`) |
| `MODE` | `proxy` | `proxy` (HTTP+SOCKS5) или `tun` (VPN) |
| `LOG_ENABLED` | `false` | Писать лог в файл |
| `LOG_FILE` | `xray-runner.log` | Путь к лог-файлу |
| `LOG_LEVEL` | `info` | Уровень файлового лога: `debug`, `info`, `warn`, `error` |
| `MASK_CREDENTIALS` | `true` | Маскировать UUID/pbk/sid в выводе |
| `XRAY_LOG_LEVEL` | `warning` | Уровень лога Xray: `debug`, `info`, `warning`, `error`, `none` |
| `KILL_SWITCH` | `false` | Блокировать трафик при падении Xray (TUN) |
| `ALLOW_INSECURE` | `false` | Уважать флаг `insecure` из подписки (отключает проверку TLS) |

### Флаги командной строки

| Флаг | Описание |
|---|---|
| `--config <путь>` | Путь к `.env` (по умолчанию `.env`) |
| `--server <индекс\|имя>` | Выбрать сервер без меню |
| `--last` | Повторить последний выбор |
| `--non-interactive` | Никогда не спрашивать; при невозможности выбора — ошибка |
| `--version` | Показать версию |

Коды возврата: `0` — успех/выход пользователем, `1` — ошибка выполнения, `2` — не удалось
выбрать сервер/подписку (для скриптов и systemd).

### Маршрутизация в режиме TUN

Программа сама маршруты ОС не настраивает — default route через `xray-tun` и исключение
(host-route) до VPN-сервера выставляет xray-core (tun-inbound с `autoRoute`, зависит от
версии/форка ядра). Если после поднятия TUN нет связи, проверьте `ip route`: должен быть
маршрут по умолчанию через `xray-tun` и отдельный маршрут до IP сервера через физический
шлюз. При его отсутствии добавьте host-route вручную:

```bash
ip route add <IP-сервера> via <шлюз> dev <интерфейс>
```

Kill switch при включении сам добавляет ACCEPT-правило до сервера.
