# xray-runner

Простая программа для запуска VPN на базе [Xray-core](https://github.com/XTLS/Xray-core).
Вы вставляете ссылку или подписку от вашего VPN-провайдера, выбираете сервер из списка —
и программа поднимает соединение. Есть два режима: системный прокси или полноценный
VPN (TUN). При выходе программа сама всё за собой убирает.

Работает на **Linux** и **Windows**.

---

## Что нужно для запуска

В комплекте всё уже разложено: сама программа и её настройки — снаружи, ядро и его
базы — в папке `bin/` рядом.

| Файл | Где | Что это |
|---|---|---|
| `xray-runner` (или `xray-runner.exe`) | снаружи | сама программа |
| `.env` | снаружи | файл настроек (можно не трогать) |
| `template.json` | снаружи | шаблон настроек — необязателен, копия зашита внутрь программы |
| `xray` (или `xray.exe`) | `bin/` | ядро Xray-core — движок соединения |
| `geoip.dat`, `geosite.dat` | `bin/` | базы для маршрутизации по странам/сайтам |

На Windows для режима VPN и маршрутизации по процессам дополнительно нужен
`wintun.dll` — он лежит в `bin/` рядом с ядром.

Ядро программа ищет сначала рядом с собой, потом в `bin/`, потом в `PATH`: старая
установка, где `xray` лежит рядом с программой, продолжает работать как была.

## Как пользоваться

### 1. Добавьте свою подписку или ссылку

Проще всего — запустить программу и добавить подписку прямо в меню (кнопка **добавить**
в списке подписок). Ссылки и подписки хранятся в папке данных (см. «Где лежат данные»),
зашифрованными (см. «Шифрование подписок»).

Поддерживаются ссылки `vless://`, `ss://` (Shadowsocks), `trojan://`, `vmess://`,
а также URL-подписки, которые провайдер даёт одной строкой.

### 2. Запустите программу

- **Linux:** откройте терминал в папке с программой и выполните `./xray-runner`.
  Для режима VPN (TUN) один раз установите службу — `sudo ./xray-runner service install`
  (см. «Служба»), — и дальше запускайте программу без `sudo`. Без службы: право
  `sudo setcap cap_net_admin+ep ./xray-runner` (см. «Режим TUN без sudo») или `sudo ./xray-runner`.
- **Windows:** запустите `xray-runner.exe`. Для режима VPN один раз установите службу —
  `xray-runner.exe service install` от имени администратора, — и дальше запускайте программу
  обычным образом. Без службы — запуск от имени администратора.

### 3. Выберите сервер

Сначала откроется список подписок:

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | двигать курсор |
| `→` | открыть подписку |
| `s` | показать полный URL подписки (по умолчанию токен маскируется) |
| `+` / `d` | добавить / удалить подписку |
| `u` | обновление ядра и гео-баз |
| `q` или `Ctrl+C` | выход |

Дальше — список серверов. Если провайдер отдаёт подписку в формате конфигов,
сначала показывается список **профилей** (локации/группы панели), и `s` на профиле
с балансировщиком разворачивает его в список серверов.

| Клавиша | Действие |
|---|---|
| `↑` / `↓` (или `k` / `j`) | двигать курсор |
| `→` | подключиться к выбранному серверу (или запустить профиль) |
| `c` | посмотреть конфиг (см. ниже) |
| `/` | поиск — подстрока по любому столбцу: имя, хост, порт, протокол, транспорт |
| `b` | замерить пинг серверов (порядок списка не меняется, самый быстрый подсвечивается) |
| `r` | обновить список из подписки |
| `←` | назад (`Esc` работает везде как запасной вариант) |
| `q` или `Ctrl+C` | выход |

### 3.1. Просмотр и сохранение конфига

`c` на списке профилей или серверов показывает конфиг, с которым пойдёт подключение:
dns, routing-правила и outbound-ы вашей панели — видно, что уходит напрямую, что в
блокировку, а что в VPN. Служебные части, которые дописывает сама программа
(локальные inbound-ы, TUN-интерфейс, уровень лога), из показа убраны.

| Клавиша | Действие |
|---|---|
| `↑` / `↓`, `PgUp` / `PgDn` | прокрутка |
| `s` | сохранить конфиг в файл |
| `←` | закрыть |

`s` кладёт конфиг в `configs/<имя подписки>/<имя сервера>.json` в папке данных — папки создаются
сами, повторное сохранение перезаписывает файл свежей версией. Файл можно открыть
любым просмотрщиком JSON. **Внимание:** в нём есть UUID/пароль вашего доступа —
не выкладывайте его никуда.

### 4. Работа во время подключения

После подключения появится экран статуса. На нём видно сервер, режим, время работы и
состояние связи. Клавиши:

| Клавиша | Действие |
|---|---|
| `m` | переключить режим PROXY ⇄ TUN на лету |
| `r` | перезапустить соединение |
| `Esc` | отключиться и вернуться к списку серверов |
| `q` | выйти из программы |

Программа сама следит за связью: раз в 15 секунд в режиме PROXY (и при маршрутизации по
процессам на Linux) и раз в 30 секунд в режиме TUN она делает проверочный запрос через VPN.
После трёх неудачных проверок подряд ядро перезапускается. Успешная проверка значит, что
VPN-сервер отвечает, но не доказывает, что трафик каждого приложения идёт через VPN.

> **Про строку «связь».** Сразу после подключения ядру нужна пара секунд, чтобы
> прогреться. Программа делает несколько попыток проверки, прежде чем показать
> «нет связи», поэтому ложных срабатываний в первый момент быть не должно. Если
> всё же увидели «нет связи» — нажмите `r`, чтобы перепроверить.

## Режимы: PROXY и TUN

**PROXY (по умолчанию)** — программа поднимает локальный прокси и прописывает его в
настройки системы. Через VPN пойдёт трафик приложений, которые уважают системный прокси
(браузеры и большинство программ). Прав администратора не требует.

- SOCKS5: `127.0.0.1:10808`, HTTP: `127.0.0.1:10809`

**TUN (полный VPN)** — весь трафик системы идёт через VPN, как у обычного VPN-клиента.
Требует права менять сеть: на Linux — `CAP_NET_ADMIN` (см. «Режим TUN без sudo») или
root, на Windows — администратора. Для этого программа сама меняет маршруты системы —
подробности в разделе «Маршрутизация в режиме TUN».

IPv6 на двух системах устроен по-разному. На Linux IPv6 мимо туннеля закрыт: программа
ставит маршруты «недоступно», и приложения переходят на IPv4, который идёт через VPN.
Более конкретные IPv6-маршруты (локальная сеть, link-local, маршруты других программ)
этим не перекрываются и работают мимо туннеля. На Windows IPv6 направляется в туннель.

**Kill switch** (`KILL_SWITCH=true` в `.env`) работает только в режиме TUN: он запрещает
трафик мимо туннеля. На Linux для этого используется своя таблица nftables
`inet xray-runner`, на Windows — фильтры Windows Filtering Platform (WFP).

- На Linux нужен nftables в ядре (он есть во всех современных дистрибутивах; программа
  `nft` не нужна — правила ставятся напрямую через netlink). Одна цепочка закрывает и
  IPv4, и IPv6. Если kill switch не включился, подключения не будет — на обеих системах.
- Мимо туннеля он пропускает DNS (порт 53), соединения ядра с VPN-серверами профиля,
  трафик, который правила профиля отправляют напрямую (`direct`), и локальный интерфейс.
  Ещё DHCPv6 и обнаружение соседей IPv6 (ICMPv6 133–137), на Windows и DHCP для IPv4:
  без них адаптер теряет адрес, пока kill switch включён. Трафик `direct` на Windows пропускается по
  программе: всё, что отправляет само ядро `bin\xray.exe` этой сессии.
- Пока ядро перезапускается после сбоя, kill switch остаётся на месте. Если в этот
  момент пропала сеть, сессия не завершается: программа ждёт сеть и поднимает
  маршруты сама, а kill switch всё это время держит трафик.
- При окончательном завершении сессии он снимается: при выходе, отключении и когда
  попытки перезапустить ядро кончились. После этого сеть снова работает напрямую — это
  не блокировка до ручного снятия.
- **Windows:** фильтры живут, пока жив процесс программы. Если её завершили аварийно
  (сняли задачу, упала), Windows сама убирает их вместе с процессом — сеть не остаётся
  закрытой. Посмотреть фильтры: `netsh wfp show filters` (от администратора), они
  называются `xray-runner kill switch`.
- **Linux:** если программу завершили аварийно (процесс убит), правила kill switch
  остаются, и сеть закрыта до следующего запуска программы с теми же правами (через
  `sudo` или с `CAP_NET_ADMIN`): при старте она снимает их сама, ещё до выбора сервера
  (см. «Изменения системы после аварийного завершения»). Снять вручную (от root) —
  таблица программы удаляется целиком, чужих правил в ней нет:

  ```bash
  nft delete table inet xray-runner
  ```

  Цепочку `XRAY_KILL` в iptables, которую оставила версия до перехода на nftables, при
  таком восстановлении программа тоже снимает.
- В режиме PROXY и при маршрутизации по процессам не действует.

Без kill switch при сбое ядра, пока программа снимает маршруты упавшего ядра и ставит
их заново для нового, трафик может уйти напрямую.

Переключиться между режимами можно прямо на экране статуса клавишей `m`. Выбор
сохраняется в `last_server.json` и при следующих запусках берётся вместо `MODE` из `.env`.

### Служба: TUN без sudo и без администратора

Всё, что требует прав, — маршруты TUN, kill switch, маршрутизацию по процессам на Linux,
само ядро в режиме TUN — может делать служба, а программа с меню работает от вашего
пользователя. Это тот же файл `xray-runner`, запущенный как служба системы:

```bash
# Linux
sudo ./xray-runner service install
# Windows (PowerShell от имени администратора)
.\xray-runner.exe service install
```

Установка копирует программу и ядро (с базами geo, на Windows — и `wintun.dll`) в папку,
куда пишет только root или администратор: `/usr/local/lib/xray-runner` на Linux,
`%ProgramFiles%\xray-runner` на Windows. С правами работает только эта копия, поэтому
подменить её из своей папки нельзя. После обновления программы установку повторите —
служба перезапустится с новой версией.

- `xray-runner service status` — установлена ли служба, отвечает ли, идёт ли сессия.
- `xray-runner service uninstall` (через `sudo` / от администратора) — удалить службу.
- Если служба есть и доступна, программа пользуется ею сама; если нет (не установлена,
  остановлена, нет доступа), всё работает как раньше — в процессе программы, с правами,
  которые у неё есть. Не пользоваться службой: `XRAY_RUNNER_NO_SERVICE=1` в `.env` или в окружении.
- Подписки, замеры, режим PROXY и системный прокси остаются в программе — у каждого
  пользователя свои. Служба получает от программы только то, через что подключаться
  (outbounds, правила маршрутизации, DNS), и сама проверяет это: поля, которые называют
  файлы, unix-сокеты, списки `ext:` и опции сокета вроде `mark` она не принимает, ключи
  сравнивает без учёта регистра, как ядро. Логи, ядро и inbound-ы — её.
- Сессия у службы одна на всех. Пока идёт чужая, подключиться в TUN нельзя: программа
  скажет, что служба занята. Если программа закрылась, не сняв сессию, служба снимает её
  сама через 10 секунд.
- Строки лога ядра служба пересылает программе, они попадают в ваш `xray-runner.log`.
  Лог самой службы: на Linux — `journalctl -u xray-runner`, на Windows —
  `%ProgramFiles%\xray-runner\log\service.log` (читают только администраторы).

**Linux.** Служба запускается systemd по первому обращению к сокету
`/run/xray-runner/control.sock`. Пользоваться ею могут root и члены группы `xray-runner`:
установка создаёт группу и добавляет в неё того, кто вызвал `sudo` (войдите в систему
заново, чтобы это вступило в силу). Другого пользователя добавьте сами:
`sudo usermod -aG xray-runner <имя>`. Служба работает от root — только root может
переносить процессы в cgroup в корне иерархии, — но без его остальных прав: из
возможностей ядра у неё `CAP_NET_ADMIN` и `CAP_NET_RAW`, файловая система доступна ей
только на чтение, кроме `/run/xray-runner` и дерева cgroup, домашние папки ей не видны.
Права читать чужие процессы (`CAP_SYS_PTRACE`) у неё нет — оно равно полному root. Поэтому
при маршрутизации по процессам соединения, открытые программой до переноса, находит ваша
программа (это ваши процессы), а служба закрывает их, проверив, что сокет ваш. Переносит
служба только ваши процессы и только если порт перенаправления слушает ваше ядро.

**Windows.** Служба `xray-runner` запускается от LocalSystem при старте системы. Программа
связывается с ней через именованный канал `\\.\pipe\xray-runner`; из сети он недоступен.
Пользоваться службой могут администраторы (программа запущена от имени администратора) и
члены локальной группы `xray-runner Users`. Просто войти в систему недостаточно: TUN и
kill switch действуют на весь компьютер, а в логе ядра видны адреса, куда ходит трафик.
Установка создаёт группу и добавляет в неё пользователя, вошедшего в систему, — даже если
права администратора для установки дал другой пользователь; кого добавила, она пишет.
Входить заново не нужно. Другого пользователя добавьте из окна администратора:

```powershell
net localgroup "xray-runner Users" <имя> /add
```

Удаление службы удаляет и группу. Остальным программа при подключении скажет, что служба
им недоступна, и будет работать без неё.

Лог службы лежит в `%ProgramFiles%\xray-runner\log`: эту папку создаёт установка, её
владелец — администраторы, и пользователь не может создать её заранее или подменить
ссылкой. Если папка всё же оказалась ссылкой (junction), установка удаляет ссылку и
создаёт папку заново; если у папки чужой владелец, установка останавливается — удалите
папку и повторите. Служба при запуске проверяет то же самое и с неподходящей папкой
работает без лога, а причину пишет в журнал событий Windows («Приложение», источник
`xray-runner`).

Пока служба не запущена (например, между падением и перезапуском), имя канала может
занять другая программа. Программа с меню к такому каналу не подключится: она проверяет,
что канал принадлежит системе или администраторам. Но и служба тогда не запустится: в её
лог попадёт «канал \\.\pipe\xray-runner уже занят» с владельцем и процессом, который его
держит. Завершите этот процесс и запустите службу снова (`services.msc` или
`sc start xray-runner`).

### Режим TUN без sudo (Linux)

Запускать всю программу от root для TUN не нужно: ей достаточно одного права —
`CAP_NET_ADMIN`, менять сетевые настройки. Выдаётся один раз:

```bash
sudo setcap cap_net_admin+ep ./xray-runner
./xray-runner
```

Программа работает от вашего пользователя, файлы остаются вашими, а право передаёт только
тем, кому оно нужно: ядру xray (создать `xray-tun`, пометить прямые соединения). Маршруты
и правила nftables программа ставит сама, через netlink, без `ip`, `iptables` и `nft`.
Проверить, что право на месте: `getcap ./xray-runner` покажет
`cap_net_admin=ep`.

- Право привязано к файлу. После замены `xray-runner` новой версией команду `setcap` нужно
  повторить. Для обновления ядра из программы повторять ничего не нужно.
- Внешние утилиты, которые ещё нужны (`ss` для маршрутизации по процессам), программа с
  этим правом ищет только в системных папках (`/usr/sbin`, `/usr/bin` и т. п.), а не по
  `PATH`. Ядро — рядом с программой, в `bin/` или в системной папке вроде `/usr/local/bin`.
- Право получает каждый, кто может запустить файл, а через подмену ядра в `bin/` — каждый,
  кто может писать в папку программы. Обычно это вы сами: папка в домашнем каталоге и так
  доступна на запись только вам. На компьютере, которым пользуются несколько человек,
  поставьте программу в папку, куда пишет только root, например `/opt/xray-runner`.
  `CAP_NET_ADMIN` — это управление сетью всего компьютера: меньше, чем `sudo`, но не пустяк.
- Остатки аварийно завершённого запуска без `sudo` программа ищет в своём журнале в
  `~/.cache/xray-runner/journal/`, остатки запуска через `sudo` — в `/run/xray-runner/`.
  Поэтому последние снимет только следующий запуск через `sudo`.
- Убрать право: `sudo setcap -r ./xray-runner`.

### Маршрутизация по процессам

Через VPN можно пустить только выбранные программы. Их список — `apps.txt` в папке
данных, заполняется клавишей `p` в меню подписок. Отдельного значения `MODE` для этого нет:
маршрутизация включается сама в режиме PROXY, когда в списке есть хотя бы одно имя.

- **Linux:** нужны nftables в ядре (5.2 или новее: правила NAT живут в таблице
  семейства `inet`), `ss` и права: служба (см. «Служба»), root или `CAP_NET_ADMIN`
  (см. «Режим TUN без sudo»). Без root cgroup создаётся внутри той, что systemd выделяет вашему сеансу
  (`user@<uid>.service`). Программы из списка переносятся в отдельную cgroup,
  их TCP и DNS заворачиваются в VPN, остальной UDP и весь IPv6 этих программ отклоняются.
  Список процессов проверяется раз в секунду, и до переноса программа работает напрямую.
  Соединения, открытые до переноса, закрываются принудительно. Если закрыть не удалось, на
  экране появится предупреждение: такие соединения идут мимо VPN, пока программа не
  переподключится. Гарантии, что мимо VPN не уйдёт ни одного соединения, нет.
- **Windows:** работает поверх TUN, нужна служба или права администратора. Программу
  определяет само ядро xray в момент соединения.

## Обновление ядра и баз

В списке подписок нажмите кнопку **обновление**. Откроется экран, где можно:

- **Обновить ядро xray** — программа скачает свежие версии с официального репозитория и
  предложит список. В шапке экрана показано, **какое ядро установлено сейчас** («Текущее
  ядро: …»), а напротив совпадающей версии в списке стоит пометка **(установлено)** —
  так видно, обновление это или откат.
- **Обновить гео-базы** — свежие `geoip.dat` / `geosite.dat`.

Обновляется только собственное ядро программы — то, что лежит рядом с ней или в `bin/`.
Если ядро найдено в `PATH` (например, его поставил пакетный менеджер), экран обновления
его не трогает, как и гео-базы рядом с ним: обновляйте его тем же способом, каким ставили.

## Частые проблемы

**«Порт занят другим процессом».** Обычно это значит, что уже запущен либо второй
экземпляр этой программы, либо другой VPN/прокси, занявший тот же локальный порт.
Закройте сторонний VPN или второй экземпляр и попробуйте снова.

**Про lock-файл.** Программа создаёт в папке данных файл
`xray_config.json.lock` и держит на нём блокировку системы, чтобы не запуститься дважды.
Файл остаётся и после выхода — так задумано. **Удалять его вручную не нужно**: блокировку
держит сам процесс, и система снимает её, как только он завершился, даже аварийно
(закрыто окно, процесс убит). Отказ появится только тогда, когда действительно работает
второй экземпляр.

**В режиме TUN нет связи.** Проверьте, что служба установлена и отвечает
(`xray-runner service status`) или что программа запущена с правами root/администратора.
Если маршруты не поднялись — смотрите раздел ниже про TUN.

**Сайты не открываются после аварийного выхода.** Если программу завершили аварийно
(процесс убит, пропало питание, система зависла), она не успевает вернуть системный
прокси. Признаки: браузер пишет, что прокси-сервер не отвечает; в настройках прокси
указан `127.0.0.1:10809`; программа при этом не запущена.

Достаточно запустить программу и подключиться к серверу снова: перед подключением она
проверяет настройку и, если там стоит **её собственный** адрес, на котором никто не слушает,
снимает его и пишет об этом на экране статуса. Остальные настройки она не трогает.

Вручную убирать нужно только в двух случаях: снять не удалось (программа скажет, почему)
или в настройках стоит чужой адрес — его оставила другая программа, и подставлять на его
место что-то своё мы не вправе. Тогда посмотрите, что сейчас настроено, и выключите
**только ручной прокси на `127.0.0.1:10809`**. Автоматическую настройку (PAC-скрипт) и
остальные поля не трогайте.

- **Windows:** «Параметры» → «Сеть и Интернет» → «Прокси-сервер» → «Настройка прокси
  вручную». Если там адрес `127.0.0.1` и порт `10809`, выключите «Использовать
  прокси-сервер». Раздел «Автоматическая настройка прокси» не меняйте.
- **GNOME:** посмотреть — `gsettings get org.gnome.system.proxy mode`, затем
  `gsettings get org.gnome.system.proxy.http host` и `… port`. Если режим `'manual'`, а
  адрес `127.0.0.1` и `10809`, выполните `gsettings set org.gnome.system.proxy mode 'none'`
  (или `'auto'`, если до программы у вас был PAC-скрипт).
- **KDE:** «Параметры системы» → «Сеть» → «Прокси» → «Без прокси». Из терминала:
  посмотреть — `kreadconfig5 --group Proxy --key ProxyType` и `--key httpProxy`; если тип
  `1`, а адрес `127.0.0.1:10809`, выполните `kwriteconfig5 --group Proxy --key ProxyType 0`.
  На Plasma 6 те же команды называются `kreadconfig6` и `kwriteconfig6`.

Команды выполняйте от своего пользователя, без `sudo`.

## Приватность

Стоит знать, какие запросы программа делает сама по себе:

- **Проверка связи.** Чтобы показать «связь есть / нет связи», программа периодически
  запрашивает страницы-заглушки: `google.com/generate_204`,
  `connectivitycheck.gstatic.com/generate_204` и `cloudflare.com/cdn-cgi/trace`. В режиме
  PROXY/TUN эти запросы идут **через VPN**. Если такое телеметрическое обращение
  нежелательно — адреса можно заменить своими через `HEALTH_CHECK_URL` в `.env`.
- **Kill switch и DNS.** Чтобы имя сервера продолжало резолвиться при обрыве, kill switch
  оставляет открытым исходящий порт `53` (DNS) на физическом интерфейсе. На Windows
  иначе нельзя: имена резолвит системная служба DNS-клиента, а не само ядро. Это
  осознанный компромисс: без него VPN не сможет переподключиться, но формально DNS-запросы
  остаются возможным каналом за пределами туннеля.
- **Обновления.** Ядро и гео-базы качаются с GitHub (`XTLS/Xray-core`,
  `Loyalsoldier/v2ray-rules-dat`). Ядро устанавливается только после сверки SHA-256 из
  официального `.dgst`.

Файл `.env` необязателен: без него действуют значения по умолчанию, а подписки

### Где лежат данные

Настройки и состояние программа хранит в папке данных пользователя: `~/.config/xray-runner/`
на Linux (под `sudo` — в папке того, кто вызвал `sudo`) и `%APPDATA%\xray-runner\` на
Windows. Там лежат подписки (`subscriptions.enc`, см. ниже), `apps.txt`, `last_server.json`,
сохранённые конфиги `configs/` и lock-файл, а на Linux ещё `hwid` и лог.

На Windows то, что относится к одному компьютеру, — `hwid` и лог — лежит в
`%LOCALAPPDATA%\xray-runner\`: `%APPDATA%` в доменных сетях копируется на другие
компьютеры, а идентификатор устройства у каждого свой. `hwid` из старой версии переносится
туда сам, с тем же значением.

Гео-базы, которые указывает панель подписки, скачиваются в кэш: `~/.cache/xray-runner/geo/`
на Linux и `%LOCALAPPDATA%\xray-runner\geo\` на Windows. Их можно удалить — при следующем
открытии подписки они скачаются снова. Старая папка `geo/` рядом с ядром удаляется сама.

Если файл с таким же именем уже лежит рядом с программой, берётся он: так продолжают
работать старые установки и запуск с флешки. Папка, из которой программу запустили,
значения не имеет — ни для этих файлов, ни для `.env`.

### Шифрование подписок

Адреса подписок содержат токены доступа к панели, поэтому список шифруется ключом, который
хранит операционная система: на Windows — DPAPI (ключ вашей учётной записи Windows), на
Linux — ключ в Secret Service (GNOME Keyring, KWallet, KeePassXC). Файл
`subscriptions.enc` откроется только у вас и только на этом компьютере; его копия сама по
себе бесполезна.

- Открытый `subscriptions.txt` в папке данных от старой версии шифруется при первом
  запуске, открытая копия удаляется.
- Чтобы добавить подписки вручную, положите `subscriptions.txt` (по одной ссылке на
  строку, `# имя` строкой выше) в папку данных — при следующем запуске он будет
  зашифрован и перенесён в список.
- **Переносной режим.** Если рядом с программой лежит непустой `subscriptions.txt`,
  программа работает с ним и **не шифрует** его: ключ ОС привязан к компьютеру, и на
  флешке зашифрованный список не открылся бы на другой машине. Чтобы включить шифрование,
  перенесите этот файл в папку данных. Пустой `subscriptions.txt` рядом с программой (его
  клали в прежние архивы) ни на что не влияет.
- **Без Secret Service** (сервер без графической сессии) список хранится как раньше —
  открытым файлом с доступом только для вас (0600), и при старте программа об этом
  сообщает.
- **Под `sudo`** ключ берётся из Secret Service того, кто вызвал `sudo`: программа
  спрашивает его от имени этого пользователя, через его сессионную шину
  (`/run/user/<uid>/bus`).
- Если связку ключей сбросили, зашифрованный список уже не открыть: программа скажет об
  этом и ничего поверх не запишет. Удалите `subscriptions.enc` и добавьте подписки заново.

Рабочий конфиг ядра (с ключами доступа к серверу) на диск не пишется: программа передаёт
его ядру напрямую, через стандартный ввод. Ни во временной папке, ни где-либо ещё его
копии нет — удалять после аварийного завершения нечего.

Пока подключение в TUN, с kill switch или по процессам меняет систему, программа ведёт
журнал этих изменений (см. следующий раздел): `/run/xray-runner/` под root,
`~/.cache/xray-runner/journal/` без root и ключ реестра `HKLM\SOFTWARE\xray-runner` на
Windows. Когда изменений не остаётся, запись удаляется, и после обычного выхода журнала
нет.

### Изменения системы после аварийного завершения

Программа, которую завершили аварийно (процесс убит, программа упала, окно консоли
закрыто раньше, чем Windows дала ей прибраться), не успевает вернуть систему как было.
Ядро завершается вместе с ней, и TUN-интерфейс пропадает с маршрутами через него. Но
остаются исключения для серверов, на Linux ещё служебная таблица `8888`, правило для
метки, блокировка IPv6 и таблица nftables `inet xray-runner` с kill switch и правилами
маршрутизации по процессам. До
перезагрузки из-за них не работал IPv6 или, с kill switch, вся сеть, а следующее
подключение в TUN отказывалось из-за «уже есть маршруты».

Поэтому каждое изменение сначала записывается в журнал, а потом делается. У каждого
запущенного экземпляра своя запись. При старте, ещё до меню, программа находит записи
процессов, которых уже нет, снимает то, что в них названо, и сообщает об этом на экране
статуса: «Сняты остатки аварийно завершённого запуска: …». Снимается только то, что
осталось в системе в точности как было поставлено. Запись, которая не читается или
названа не так, как программа её пишет, не выполняется.

- Записи прошлой загрузки системы удаляются без действий: перезагрузка сняла всё сама.
- Запись работающего процесса — например, второй копии программы из другой папки —
  не трогается.
- Журнал доступен только тем правам, с которыми делались изменения: под root он в
  `/run`, куда пишет только root, на Windows — в `HKLM`, куда пишут только
  администраторы. Остатки запуска через `sudo` снимет следующий запуск через `sudo`,
  остатки запуска от администратора — следующий запуск от администратора.
- Служба пишет в те же места (`/run/xray-runner`, `HKLM`) и при каждом своём старте
  снимает остатки — свои после сбоя и оставшиеся от запусков через `sudo` или от
  администратора до её установки. Упавшую службу система перезапускает сама.
- Если снять не удалось, программа говорит об этом, запись остаётся, и следующий запуск
  попробует снова. Вручную — командами из разделов про kill switch и маршруты или
  перезагрузкой.

### Маршрутизация в режиме TUN

Программа сама меняет маршруты системы, а при выходе снимает только то, что поставила:

- весь IPv4 направляется в `xray-tun` двумя половинами, `0.0.0.0/1` и `128.0.0.0/1`;
- до каждого IP VPN-сервера ставится отдельный маршрут через физический шлюз, чтобы
  соединение ядра с сервером не ушло в сам туннель;
- на Linux добавляются служебная таблица `8888` и правило для трафика с меткой `255`
  (то, что профиль отправляет напрямую), а для IPv6 — маршруты `unreachable` `::/1` и
  `8000::/1`;
- на Windows IPv6 направляется в туннель половинами `::/1` и `8000::/1`, IPv6-адреса
  серверов исключаются так же, как IPv4.

Перед изменениями программа сверяется с таблицей маршрутов. Если нужные ей записи уже
есть, подключение отменяется с перечнем найденных записей, и в системе ничего не
меняется. Чужие маршруты программа не перезаписывает и не удаляет, таблицы целиком не
очищает. Свои остатки от аварийно завершённого запуска она снимает при старте сама, по
журналу (см. «Изменения системы после аварийного завершения»). Поэтому такой отказ
значит, что записи поставил другой VPN, или что остатки не удалось снять по журналу —
причина тогда на экране статуса. Удалите их вручную или перезагрузкой, но сначала
убедитесь, что это не записи другой программы:

```bash
# Linux
ip route; ip -6 route; ip rule; ip route show table 8888; nft list table inet xray-runner
# Windows (PowerShell)
Get-NetRoute -PolicyStore ActiveStore
```

При перезапуске ядра маршруты снимаются и ставятся заново для нового TUN-интерфейса.
