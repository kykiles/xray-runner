# Ручная проверка тестовой сборки на Windows

Сборку делает CI (workflow «Bundle (Windows)») на каждый пуш: коммит — в имени
папки, ядро — версии `xray.MinVersion`, архив ядра проверен по контрольной сумме
из релиза; wintun и гео-базы лежат в `bin/`.

Займёт 20–30 минут. Нужна Windows 10 или 11, для режима TUN — права администратора.

**Не проверяйте по удалённому доступу (RDP, AnyDesk):** в пунктах 2 и 3 весь
трафик уходит в туннель, а потом сеть пропадает на пару минут — связь с машиной
оборвётся.

## Подготовка

1. Распакуйте архив целиком в простую папку, например `C:\xray-test`. Не в
   `Program Files`.
2. Откройте PowerShell **от имени администратора** и перейдите в эту папку:

   ```
   cd C:\xray-test\xray-runner-windows-<коммит>
   .\xray-runner.exe
   ```

   Запуск из консоли, а не двойным щелчком: так видно сообщения и программа точно
   читает `.env` из своей папки. Если Windows предупредит о неизвестном издателе,
   нажмите «Подробнее» → «Выполнить в любом случае».
3. В шапке должно быть `xray-runner <коммит>` — тот же, что в имени папки. Если
   там другая версия — запущена не та сборка.
4. Добавьте свою подписку (`+` в списке подписок).

Лог программы: `%APPDATA%\xray-runner\xray-runner.log` (вставьте этот путь в
адресную строку Проводника). Он перезаписывается при каждом запуске, поэтому
после проблемного шага **сохраните копию лога, прежде чем запускать снова**.

## 1. Режим PROXY: включение и откат прокси

1. Заранее посмотрите «Параметры» → «Сеть и Интернет» → «Прокси-сервер» и
   запомните, что там стоит.
2. Подключитесь к серверу в режиме PROXY.
3. **Ожидается:** в настройках прокси включён `127.0.0.1:10809`, браузер
   открывает сайты, на https://ifconfig.me виден IP VPN-сервера.
4. Нажмите `Esc` (отключиться), затем `q` (выход).
5. **Ожидается:** настройки прокси ровно такие, как в п. 1. Сайты открываются
   напрямую.

## 2. Режим TUN: маршруты и их снятие

1. Подключитесь в режиме TUN (клавиша `m` на экране статуса переключает режим).
2. В **другом** окне PowerShell выполните `route print -4`.
3. **Ожидается:** есть строки `0.0.0.0  128.0.0.0  10.0.0.1` и
   `128.0.0.0  128.0.0.0  10.0.0.1`, а для IP VPN-сервера — отдельная строка с
   маской `255.255.255.255` через ваш обычный шлюз.
4. На https://ifconfig.me виден IP VPN-сервера, строка «связь» — «ок».
5. Выйдите `q`. Снова `route print -4`.
6. **Ожидается:** строк с `10.0.0.1` и строки для IP сервера больше нет, сайты
   открываются напрямую.

## 3. Обрыв сети в TUN (новое, G06)

Раньше сессия при этом завершалась с ошибкой и возвращала вас в меню.

1. Подключитесь в TUN, дождитесь «связь: ок».
2. Отключите сеть: выключите Wi-Fi или адаптер Ethernet
   («Сетевые подключения» → правой кнопкой → «Отключить»).
3. Подождите **2–3 минуты**. Проверка связи раз в 30 секунд, после трёх неудач
   ядро перезапускается.
4. **Ожидается:** сначала «Health-check не прошёл 3 раза подряд — перезапускаю
   xray…», затем «**Нет сети: жду её, соединение восстановится само.**».
   Программа остаётся на экране статуса, в меню не выходит.
5. Включите сеть **на том же адаптере**.
6. **Ожидается:** в течение минуты «связь» снова «ок», на https://ifconfig.me
   IP VPN-сервера, переподключаться вручную не нужно.

Если сеть вернулась через **другой** адаптер (был Wi-Fi, стал кабель), сессия
завершится с сообщением «физический адаптер сменился… подключитесь заново». Так и
задумано.

## 4. Ядро не переживает убитую программу (новое, G07)

1. Подключитесь в режиме **PROXY**.
2. Откройте Диспетчер задач → «Подробности» и найдите `xray-runner.exe` и
   `xray.exe`.
3. Снимите задачу `xray-runner.exe` (правой кнопкой → «Снять задачу»).
4. **Ожидается:** `xray.exe` исчезает из списка сам, в течение пары секунд.
   Раньше он оставался висеть.
5. Сайты сейчас не открываются: системный прокси всё ещё указывает на
   `127.0.0.1:10809`. Это ожидаемо — убитая программа не успела его снять.
6. Запустите программу снова и подключитесь.
7. **Ожидается:** подключение проходит без ошибки «порт занят», а на экране
   статуса сообщение, что прокси, оставшийся от аварийного запуска, снят.
   После выхода прокси выключен, сайты открываются.

Можно повторить в TUN. Там после снятия задачи на машине может остаться маршрут к
IP сервера, и следующее подключение в TUN откажется с «уже есть маршруты, которые
ставит TUN». Это известное поведение, а не новая ошибка. Снять остаток можно
командой `route delete <IP сервера>` от администратора. Напишите, случилось ли так.

## 5. Сохранение настроек (затронуто G02)

1. Добавьте вторую подписку, потом удалите её.
2. Клавишей `p` выберите пару процессов для маршрутизации по процессам и
   сохраните.
3. Переключите режим клавишей `m`.
4. Выйдите и запустите программу снова.
5. **Ожидается:** список подписок, выбранные процессы и режим сохранились.
6. В папке программы и в `%APPDATA%\xray-runner` **нет** лишних файлов вида
   `.apps.txt-….tmp` или `.subscriptions.txt-….tmp`.

## 6. Обновление ядра и гео-баз (затронуто G04)

1. В списке подписок нажмите `u`.
2. Обновите гео-базы.
3. Обновите ядро, выбрав ту же версию, что уже стоит (помечена «установлено»).
4. **Ожидается:** обе установки завершаются без ошибок, после них подключение
   работает.

## Если что-то пошло не так

- Сеть не работает после выхода: проверьте «Прокси-сервер» в параметрах
  (выключите ручной `127.0.0.1:10809`) и `route print -4` (строки с `10.0.0.1`
  снимет перезагрузка).

## Что прислать

По каждому пункту 1–6: «ок» или что увидели вместо ожидаемого. Для пунктов с
проблемой приложите сохранённый лог. Программа не пишет туда сам конфиг с
ключами, но адреса серверов в логе есть — просмотрите его перед отправкой.
