# Задание для Claude Code

**Человеку — три шага:**

1. Распаковать архив целиком в любую папку.
2. Открыть PowerShell **от имени администратора** (Пуск → набрать `PowerShell` →
   правой кнопкой → «Запуск от имени администратора»), перейти в эту папку и
   запустить оттуда Claude Code. Это важно: сам он права повысить не может —
   Windows спрашивает подтверждение у человека.
3. Скопировать весь текст ниже (от строки «Ты выполняешь» и до конца) и вставить
   в Claude Code одним сообщением.

---

Ты выполняешь разовую проверку прав доступа для приложения xray-runner на этой
Windows-машине. Это не задача на разработку: чинить, улучшать и дорабатывать
ничего не надо.

**Контекст.** Приложение во время работы кладёт во временную папку рабочий
конфиг, в котором лежат адрес сервера, логин и пароль. Эта папка должна быть
закрыта от других обычных пользователей того же компьютера. Проверка «изнутри» —
чтение списка доступа — уже сделана раньше и прошла. Осталось единственное, чего
нельзя проверить из-под самого владельца: завести вторую учётную запись и
попробовать открыть чужой конфиг от её имени. Ровно это и делает набор, лежащий
рядом с тобой.

В папке два файла: `test-windows-f07.ps1` и `app_tests.exe` — уже собранный набор
тестов, работает сам по себе, Go и компиляторы не нужны.

**Жёсткие рамки, соблюдай буквально:**

1. **Ничего не чинить.** Если проверка падает — это и есть результат, ради
   которого всё затевалось. Не правь код, не редактируй скрипт, не меняй права
   папок и настройки Windows, чтобы «стало проходить». Падение надо передать, а
   не устранить.
2. **Ничего не устанавливать** и не скачивать. Интернет для этой задачи не нужен.
3. **Не запускать тесты в обход скрипта.** Отдельные тесты из `app_tests.exe`
   вручную не гоняй: главная проверка без временной учётной записи просто
   пропустится, и ты примешь пропуск за успех. Учётку заводит скрипт.
4. **Один прогон.** Отработал и выдал отчёт — задача закрыта, даже если в отчёте
   есть FAIL. Повторять с изменениями не надо.
5. **Не удаляй и не переименовывай файлы** в этой папке.

**Что сделать:**

Шаг 1. Проверь права администратора:

```powershell
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
```

Если `False` — **остановись и ничего не запускай**. Скажи человеку: нужно
закрыть тебя, открыть PowerShell через правую кнопку → «Запуск от имени
администратора» и запустить Claude Code оттуда. Сам повысить права ты не
сможешь, и пытаться обойти это не надо.

Шаг 2. Запусти проверку одной командой:

```powershell
powershell -ExecutionPolicy Bypass -File .\test-windows-f07.ps1
```

Скрипт заведёт временную учётную запись вида `xrt123456` со случайным паролем,
прогонит от её имени проверки и удалит её обратно — в том числе если что-то
упадёт. Занимает около минуты. Дождись строки «Готово».

Шаг 3. Найди появившийся рядом файл `xray-runner-f07-<дата>.md`, прочитай его
целиком и напиши человеку короткую сводку своими словами:

- итог каждой из трёх проверок: PASS, FAIL или SKIP;
- если есть FAIL — какие именно тесты упали и что написано в их выводе;
- если где-то в выводе встретилась строка со словами **«контроль не прошёл»** —
  скажи об этом отдельно и прямо: это значит, что проверка вообще не состоялась
  и её результату верить нельзя, даже если формально всё зелёное;
- если главная проверка (первая строка таблицы) оказалась **SKIP** — это тоже
  повод сказать отдельно: значит временную учётную запись завести не удалось и
  проверка не выполнялась.

Шаг 4. Скажи человеку, что файл `xray-runner-f07-<дата>.md` нужно отправить
разработчику **целиком, файлом**, а не пересказом — в нём полный вывод тестов,
по которому видно, что именно не совпало.

**Если скрипт упал или оборвался:**

Не переписывай его и не запускай заново с изменениями. Сохрани весь вывод как
есть, передай человеку и скажи, на каком шаге остановилось. Отдельно проверь,
что временная учётная запись всё-таки убрана:

```powershell
Get-LocalUser -Name 'xrt*' -ErrorAction SilentlyContinue
```

Если она осталась — назови человеку её имя и предложи удалить командой
`Remove-LocalUser -Name <имя>`, но сам без его явного согласия не удаляй.

**Как читать результат.** Слово FAIL не обязательно означает поломку программы.
У проверки «Temp этой машины» FAIL значит, что временная папка на этом
компьютере открыта слишком широко — в таком случае приложение намеренно
откажется стартовать, и это правильное поведение, а не дефект. Твоя задача — не
оценивать и не делать выводов о качестве кода, а точно и полно передать, что
получилось.
